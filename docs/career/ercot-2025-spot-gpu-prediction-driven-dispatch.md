# ERCOT 2025 Spot GPU 预测驱动调度

## 项目定位

本项目面向“业务预测与决策智能”岗位，构建**真实 Spot GPU 作业重放下的预测驱动数据中心日前调度**。它以购电价、光伏出力和风电出力的日前预测为上游，以 Spot 作业执行、购电和储能调度为下游，并以真实能源信号结算预测导致的成本差异。

项目是跨域数据驱动的反事实重放实验：真实生产级 GPU 作业轨迹被重放到 ERCOT 2025 年能源信号上。它不是阿里巴巴集群在 Houston 或 ERCOT 的历史运行记录，也不将系统级风光解释为 Houston 本地发电数据。

## 数据边界

| 数据 | 作用 | 已核验边界 |
| --- | --- | --- |
| ERCOT 2025 年 `LZ_HOUSTON` DAM 价格 | 日前购电成本信号与预测目标 | 8,760 个小时，价格字段无缺失 |
| EIA ERCO 2025 年 `NG: SUN` 与 `NG: WND` | 系统级风电、光伏信号与预测目标 | 时间索引全年逐小时连续；两个目标各有 48 个原始缺失时点 |
| Alibaba Spot GPU 作业表 | 可延迟作业的重放到达、资源请求与持续时间 | 51,154 个 `Spot` 作业；提交时间为相对秒数，无公开绝对日期、地点或时区 |
| Alibaba GPU 节点表 | 作业资源请求的节点容量语境 | 4,278 个节点；不提供实测功耗 |

原始文件及其来源、哈希和字段说明保留在 `data/energy/` 与 `data/workload/`。求职线只读取经论文线生成并审计的公共年度能源表；论文线的固定窗口输入快照不得充当求职线训练、验证或测试划分。

## 第一阶段范围

### 上游预测

每个日前截止点预测下一调度窗口的：

1. `LZ_HOUSTON` DAM 价格；
2. ERCOT 系统级光伏信号；
3. ERCOT 系统级风电信号。

训练、验证和测试必须严格按时间顺序切分。每次预测只使用截止点之前可获得的数据，且每个正式窗口必须通过时间连续性和缺失值检查。第一阶段不对原始缺失时点进行隐式填补；只使用记录在输入清单中的合格窗口。

### 作业重放与日前调度

Spot 作业使用提交时间、资源请求和持续时间构造相对时间重放负荷。重放锚点、时间缩放、作业可延迟规则，以及 GPU 资源到调度负荷的转换必须单独配置、可复现并在报告中披露。由于节点表没有实测功耗，第一阶段不得将转换后的负荷称为实测 MW。

预测值仅作为日前调度输入。调度层决定 Spot 作业的执行时段、购电和储能动作；实际价格、风电和光伏信号只在事后结算时使用。

### 当前负荷边界与后续扩展

第一阶段是**单层 Spot 柔性负荷**情景：只重放 `job_type=Spot` 的作业，并将其聚合工作量作为可在明确的 3 小时窗口内移峰的需求；`job_type=HP` 的高优先级作业不进入当前模型。该 3 小时窗口是本项目的反事实调度假设，不是原始数据集对 Spot 作业承诺的 SLA。

因此，当前结果不得表述为“同时调度 HP 与 Spot 的真实数据中心负荷”，也不得把 HP 当作已建模的刚性基线。若后续扩展为双层负荷，必须将 HP 建模为按时服务、不可移峰的背景负荷，仅允许 Spot 负荷调度；两类工作量还必须共享同一套 GPU 工作量到容量或功率的映射。该扩展需要单独设计、重新验证和重新报告，不能改变第一阶段的结论。

## 实验对照与指标

每个合格测试窗口必须同时输出：

1. **完全信息调度**：以测试窗口真实价格与真实风光信号为事后参考；
2. **基线预测调度**：以已记录的朴素时间序列预测作为输入；
3. **特征模型预测调度**：以特征模型预测作为输入，并与验证部署判据分开呈现；只有该模型在验证集上获准时，才可以将其作为通过验证的展示结论。

预测层报告价格、光伏和风电各自的 MAE 与 RMSE。决策层以真实值结算总成本、购电成本、可再生能源弃电量、储能吞吐量和 Spot 作业服务指标。模型预测调度相对完全信息调度的实际结算成本差额定义为决策遗憾。

## 运行与验收状态

在项目根目录执行：

```powershell
conda run -n scip_env python -m experiments.career ercot-2025-spot-gpu-day-ahead
```

结果包位于 `outputs/career/ercot_2025_spot_gpu_prediction_driven_dispatch/day_ahead/`。其中 `models/forecast_validation_metrics.csv` 记录逐目标 MAE、RMSE 和 NMAE，`results/decision_metrics.csv` 记录三种能源信息情景的实际结算和决策遗憾；`run_metadata.json` 记录输入 SHA-256 与验证部署判据。

已完成的一次正式运行中，基线的验证汇总 NMAE 为 `0.3294212438148784`，特征模型为 `0.3512603801165956`。因此本运行的 `feature_model_deployable` 为 `false`：特征模型仅保留为已计算的对照情景，不能作为“验证通过”或可部署的求职展示结论。后续若替换模型，必须重新运行同一固定验证集，并由新结果包中的判据决定状态。

所有图和结果仍遵守三个解释边界：

- Spot 作业是反事实重放，不代表 Alibaba 在 ERCOT 或 Houston 的真实运行；
- ERCO 风光是系统级情景信号，不是数据中心本地实测发电；
- GPU-hour 工作量映射为利用率是代理，不是实测功耗、实测 MW 或实测集群利用率。

## 明确排除项

- 不把当前固定分时电价称为市场价格预测；
- 不使用随机打乱的时间序列划分；
- 不把未来真实值作为预测值输入；
- 不将优化目标值当作实际结算成本；
- 不在第一阶段加入 GPU 工作负载预测、碳优化、概率预测或鲁棒优化。

GPU 工作负载预测和碳优化仅在完成 GPU 资源到功耗的可审计转换、且选择不含所需目标缺失值的连续窗口后，才可单独评估是否扩展。
