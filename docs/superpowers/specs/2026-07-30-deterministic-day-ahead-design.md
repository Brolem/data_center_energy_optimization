# 共和县数据中心确定性日前运行优化设计

## 1. 目标

在现有 Google 2019 聚合 CPU 轨迹模型基础上，建立一个 24 小时确定性日前运行优化模型。模型使用青海省海南州共和县的典型风光场景和目标论文的青海分时电价，联合优化算力时移、光伏利用、风电利用、电网购电和电储能运行。

一级优化目标为最小化下列四项成本：

1. 电网购电费用；
2. 光伏运行维护费用；
3. 风电运行维护费用；
4. 电储能运行维护费用。

一级成本达到最优后，二级优化在不实质增加一级成本的条件下最小化柔性任务总延迟，从而消除同一电价时段内的等价调度结果。

## 2. 研究范围

### 2.1 本阶段包含

- 24 小时确定性日前调度；
- Google 2019 聚合 CPU 轨迹的代表日；
- 30% 柔性算力和 3 小时最大延迟；
- 固定 PUE 1.10；
- 光伏、风电、电网和电储能；
- 新能源利用与弃电显式建模；
- 五组对比算例；
- 成本一级优化和任务延迟二级优化；
- CSV、JSON、LP 和图片结果；
- 完整的物理守恒、成本复算和模块有效性测试。

### 2.2 本阶段不包含

- 日内滚动修正和预测误差；
- 随机、鲁棒或区间优化；
- 内燃机、燃气锅炉、冷热联供和冰蓄冷；
- 天然气费用、碳交易费用和需求响应补贴；
- 算力服务缺口和负荷削减；
- 向电网售电；
- 连续 28 天联合优化。

上述内容可在确定性日前模型通过验证后作为扩展研究。

## 3. 数据与场景

### 3.1 算力负荷

输入仍为 `data/instance_usage_grouped_300_seconds_month.csv`。数据包含 8,064 个连续 5 分钟聚合点，即 28 天。先按小时聚合，再选择与 28 天平均 CPU 曲线均方根距离最小的第 8 天作为 24 小时代表日。

Google 轨迹没有公开这 28 天的真实日期和时区。因此，不把第 8 天声称为 2019 年 5 月 8 日，而只将代表日的小时 0–23 解释为部署到共和县后的中国标准时间小时。

### 3.2 地理位置

目标论文只说明数据中心位于青海省海南州，没有公开精确地址。场景采用共和县县城位置作为公开位置代理：

\[
\phi=36.4137534^\circ\mathrm{N},\qquad
\lambda=100.1339764^\circ\mathrm{E}.
\]

该位置必须在元数据和论文中标注为位置代理，不得描述为目标论文数据中心的真实坐标。

### 3.3 气象数据

通过 NASA POWER 小时接口请求以下参数：

- `ALLSKY_SFC_SW_DWN`：太阳辐射；
- `T2M`：2 米环境温度；
- `WS50M`：50 米风速。

请求时间标准必须显式设为 UTC。下载覆盖本地 2019 年 5 月 1 日 00:00 至 5 月 28 日 23:00 所需的 UTC 边界数据，再转换为 `Asia/Shanghai`，最后筛选出连续 672 个本地小时。

NASA POWER 的地方太阳时不等于中国标准时间，因此不得直接用地方太阳时与分时电价合并。NASA POWER 数据代表区域气象条件，不代表场站实测值。

原始数据保存为：

`data/gonghe_nasa_power_20190501_20190528_hourly_cst.csv`

该文件必须保留本地时间、UTC 时间、太阳辐射、环境温度、50 米风速以及逐时计算的光伏和风电可用功率。

### 3.4 24 小时典型气象日

风光功率是气象变量的非线性函数，处理顺序固定为：

1. 对 672 个原始小时逐时计算光伏和风电可用功率；
2. 按中国标准时间小时 0–23 对 28 天逐时功率取均值；
3. 同时计算同小时的平均太阳辐射、平均温度和平均风速，用于展示和复核。

不得先平均风速、温度或太阳辐射后再计算风光功率。

派生的 24 小时场景保存为：

`data/gonghe_typical_may_day_energy_scenario.csv`

该场景用于主实验。28 天原始数据仅用于构造典型气象日，不意味着主模型执行连续 28 天调度。

### 3.5 分时电价

采用目标论文图 6 的青海分时电价，并按中国标准时间设置：

| 时间 | 时段 | 电价（CNY/kWh） |
|---|---:|---:|
| 00:00–08:00 | 谷段 | 0.1804 |
| 08:00–09:00 | 平段 | 0.4489 |
| 09:00–13:00 | 峰段 | 0.7174 |
| 13:00–18:00 | 平段 | 0.4489 |
| 18:00–23:00 | 峰段 | 0.7174 |
| 23:00–24:00 | 平段 | 0.4489 |

所有成本统一使用 CNY，不进行美元换算。

## 4. 参数尺度

### 4.1 服务器与数据中心

采用目标论文的服务器数量和单台最大功率，同时将空闲功率比例设为 0.60：

| 参数 | 数值 |
|---|---:|
| 服务器数量 | 12,500 |
| 单台最大功率 | 0.55 kW |
| 单台空闲功率比例 | 0.60 |
| 单台空闲功率 | 0.33 kW |
| CPU 利用率上限 | 0.90 |
| PUE | 1.10 |

单台服务器功率采用聚合线性模型：

\[
P_{\mathrm{server},t}
=0.33+0.22u_t\quad\mathrm{kW}.
\]

服务器集群 IT 功率为：

\[
P_t^{\mathrm{IT}}
=12500P_{\mathrm{server},t}/1000
=4.125+2.75u_t\quad\mathrm{MW}.
\]

数据中心总功率为：

\[
P_t^{\mathrm{DC}}
=1.10P_t^{\mathrm{IT}}.
\]

当 \(u_t=0.90\) 时：

\[
P_{\max}^{\mathrm{DC}}
=1.10(4.125+2.75\times0.90)
=7.26\quad\mathrm{MW}.
\]

空闲功率比例 0.60 是本研究场景设定，不得写成目标论文提供的参数。

### 4.2 光伏

采用目标论文参数：

| 参数 | 数值 |
|---|---:|
| 光伏面积 | 20,000 m² |
| 基准转换效率 | 0.15 |
| 运行维护成本 | 0.016 CNY/kW |

逐时光伏功率采用目标论文式（4），根据太阳辐射、环境温度和风速修正组件温度及转换效率。在 25°C、1,000 W/m²条件下，名义功率为 3.0 MW。

光伏运行维护费只对实际利用的光伏功率计费。

### 4.3 风电

采用目标论文装机参数：

| 参数 | 数值 |
|---|---:|
| 风机数量 | 33 |
| 单台额定功率 | 200 kW |
| 总装机容量 | 6.6 MW |
| 运行维护成本 | 0.018 CNY/kW |

目标论文没有公开风机切入、额定和切出风速，因此功率曲线采用已有 NREL 参数：

| 参数 | 数值 |
|---|---:|
| 切入风速 | 3 m/s |
| 额定风速 | 11.4 m/s |
| 切出风速 | 25 m/s |

风电运行维护费只对实际利用的风电功率计费。正文必须区分目标论文的装机容量参数和 NREL 的风机功率曲线参数。

### 4.4 电储能

采用目标论文的电储能参数：

| 参数 | 数值 |
|---|---:|
| 储能容量 | 1.0 MWh |
| 最大充电功率 | 0.4 MW |
| 最大放电功率 | 0.25 MW |
| 充电效率 | 0.95 |
| 放电效率 | 0.90 |
| 运行维护成本 | 0.18 CNY/kW |
| 最大充电或放电活动时段数 | 16 |

SOC 约束采用已确认的研究场景设定：

| 参数 | 数值 |
|---|---:|
| 最小 SOC | 0.10 |
| 最大 SOC | 0.90 |
| 初始 SOC | 0.50 |
| 日末 SOC | 0.50 |

目标论文没有公开电储能自放电率和爬坡限值的数值，本阶段不加入这两项，不得自行补充数值。

### 4.5 电网

精简电力模型不包含目标论文中的 6 MW 内燃机，因此不能直接采用论文的 2 MW 电网交换上限。

电网容量按最大数据中心功率和最大储能充电功率推导：

\[
P_{\max}^{\mathrm{grid}}
=7.26+0.40
=7.66\quad\mathrm{MW}.
\]

统一约束为：

\[
0\leq P_t^{\mathrm{grid}}\leq7.66\quad\mathrm{MW}.
\]

该设置保证所有算例使用相同电网容量，`grid_only` 在 CPU 容量上限处可行，并且不会因电网容量过小而人为禁止储能充电。

## 5. 优化模型

### 5.1 算力调度

令 \(a_t\) 为小时 \(t\) 到达的聚合 CPU 负荷，\(u_t\) 为小时 \(t\) 调度后的 CPU 负荷。固定参数为：

\[
\rho=0.30,\qquad
D_{\max}=3\ \mathrm{h}.
\]

不可时移部分 \((1-\rho)a_t\) 必须在到达小时执行。柔性部分 \(\rho a_t\) 可从到达小时 \(o\) 分配到 \(o,\ldots,\min(o+3,23)\)。令 \(x_{o,t}\) 表示从小时 \(o\) 分配到小时 \(t\) 的柔性 CPU 负荷，则：

\[
\sum_{t=o}^{\min(o+3,23)}x_{o,t}
=\rho a_o,
\]

\[
u_t
=(1-\rho)a_t+\sum_o x_{o,t},
\]

\[
0\leq u_t\leq0.90.
\]

不允许算力服务缺口、任务删除或跨越日末执行。

### 5.2 新能源分配

光伏和风电分别满足：

\[
P_t^{\mathrm{solar,use}}
+P_t^{\mathrm{solar,curt}}
=P_t^{\mathrm{solar,avail}},
\]

\[
P_t^{\mathrm{wind,use}}
+P_t^{\mathrm{wind,curt}}
=P_t^{\mathrm{wind,avail}}.
\]

所有利用量和弃电量均非负。弃电作为输出指标，不进入一级成本目标。

### 5.3 储能

每小时储能能量平衡为：

\[
E_{t+1}
=E_t
+0.95P_t^{\mathrm{ch}}\Delta t
-\frac{P_t^{\mathrm{dis}}\Delta t}{0.90}.
\]

功率和能量约束为：

\[
0\leq P_t^{\mathrm{ch}}\leq0.4,
\]

\[
0\leq P_t^{\mathrm{dis}}\leq0.25,
\]

\[
0.1\leq E_t/1.0\leq0.9,
\]

\[
E_0=E_{24}=0.5\quad\mathrm{MWh}.
\]

设置独立的充电和放电二进制状态，保证同一小时不能同时充放电。按目标论文式（39）复现：

\[
\sum_{t=0}^{23}
\left(z_t^{\mathrm{ch}}+z_t^{\mathrm{dis}}\right)
\leq16.
\]

该式在小时离散模型中限制充电或放电活动时段总数。结果中使用“活动时段数”这一准确表述。

### 5.4 功率平衡

每小时满足：

\[
P_t^{\mathrm{grid}}
+P_t^{\mathrm{solar,use}}
+P_t^{\mathrm{wind,use}}
+P_t^{\mathrm{dis}}
=P_t^{\mathrm{DC}}
+P_t^{\mathrm{ch}}.
\]

电网购电功率非负，不允许售电。

## 6. 两层目标

### 6.1 一级目标：最低运行成本

功率变量以 MW 表示，成本系数以 CNY/kWh 或 CNY/kW 表示，时间步长为 1 小时。因此统一乘以 1,000：

\[
\begin{aligned}
\min C_{\mathrm{DA}}
=1000\sum_{t=0}^{23}
\big[
&\lambda_tP_t^{\mathrm{grid}}
+0.016P_t^{\mathrm{solar,use}}\\
&+0.018P_t^{\mathrm{wind,use}}
+0.18(P_t^{\mathrm{ch}}+P_t^{\mathrm{dis}})
\big]\Delta t.
\end{aligned}
\]

一级模型的相对最优间隙设为 \(10^{-6}\)。

### 6.2 二级目标：最低任务总延迟

一级模型得到可行最优成本 \(C^*\) 后，二级模型增加：

\[
C_{\mathrm{DA}}\leq C^*+0.01\quad\mathrm{CNY},
\]

并最小化：

\[
D
=\sum_o\sum_t(t-o)x_{o,t}.
\]

0.01 CNY 是二级优化允许的最大成本数值容差。二级目标不得以加权和或任意微小权重并入一级目标。

## 9. 异常处理

以下情况直接报错，不自动填补或削减需求：

- 气象数据不是连续 672 个中国标准时间小时；
- 时间戳重复、缺失或顺序错误；
- NASA POWER 缺失值未处理；
- 24 小时典型场景不是小时 0–23 的唯一完整序列；
- 风光功率与气象数据及设备参数不一致；
- 分时电价时段或数值与设计不一致；
- CPU 到达量、调度量或容量约束不可行；
- 电网、风光和储能无法满足功率平衡；
- SCIP 未获得可行解；
- 二级优化违反一级成本容差。

不得自动引入算力服务缺口变量来恢复可行性。

## 10. 验证计划

### 10.1 数据验证

1. 验证气象源数据转换后为连续 672 小时且无缺失。
2. 验证所有时间戳均为中国标准时间且不存在重复。
3. 验证逐时风光功率先于 28 天同小时平均计算。
4. 验证派生 24 小时场景与源数据独立重算结果一致。
5. 验证电价时段和值与目标论文图 6 一致。
6. 验证代表日仍为第 8 天。

### 10.2 参数与物理约束验证

1. 验证空闲功率比例为 0.60。
2. 验证 \(P_t^{\mathrm{IT}}=4.125+2.75u_t\)。
3. 验证 PUE 为 1.10。
4. 验证电网容量为 7.66 MW。
5. 验证每小时功率平衡。
6. 验证电网功率非负且不超过容量。
7. 验证光伏、风电利用和弃电守恒。
8. 验证 CPU 总量守恒、0.90 容量上限和 3 小时最大延迟。
9. 验证 SOC 范围、初末相等和能量平衡。
10. 验证充放电互斥且活动时段数不超过 16。

### 10.3 成本与两层目标验证

1. 独立重算四项成本。
2. 验证总运行成本等于四项成本之和。
3. 验证二级结果不超过一级成本 0.01 CNY。
4. 验证二级任务总延迟不高于一级解的任务总延迟。
5. 验证 `joint` 成本不高于 `renewables_shift`。
6. 验证 `renewables_storage` 成本不高于 `renewables_only`。

### 10.4 模块有效性验证

1. 使用合成高风光场景验证弃电量和弃电率。
2. 使用峰谷价场景验证储能能够谷充峰放。
3. 使用无经济价差场景验证储能允许选择零运行。
4. 使用 \(u=0.90\) 的合成负荷验证 `grid_only` 可行。
5. 验证默认场景不存在算力服务缺口。
6. 若 CPU 容量不足，必须返回不可行状态或明确错误。

## 11. 结果解释原则

- 储能零充放电可能是运维成本、效率和电价差共同作用下的经济最优结果，不直接判定为模块失效。
- 储能模块是否有效由合成峰谷价测试、SOC 变化和成本比较共同验证。
- 新能源弃电不进入一级目标；弃电由供需、储能和不允许售电共同决定。
- 算力时移由硬约束保证服务完整性，二级目标只用于消除等价解，不改变一级经济目标。
- 24 小时典型气象日用于主实验，28 天源数据用于构造场景和后续稳健性扩展。
- 本模型属于目标论文电力子系统的确定性日前扩展，不是其冷热电多能源系统的完整复现。

## 12. 后续扩展顺序

确定性日前模型完成并通过验证后，扩展顺序为：

1. 28 个逐日场景的稳健性分析；
2. 日前预测与日内实际数据构造；
3. 每小时滚动的日内修正模型；
4. 日前计划偏差成本和备用约束；
5. 必要时加入内燃机、天然气和碳交易模块。
